# 实现决策

## 2026-10-18｜先建立可运行的单体工程

- 问题：如何在 24 小时内交付可部署页面与服务端主链路？
- 选择：沿用 Sites Vinext 模板，React／TypeScript 统一实现页面、接口和计算。
- 依据：项目文件夹无代码；本地模板和 Sites 托管可用。
- 影响：不引入单独 Python 服务、数据库或任务队列。

## 2026-10-18｜开发期默认使用合成演示数据

- 问题：当前没有已验证的扶摇／iFinD 接口或模型 API 凭据，能否先展示流程？
- 选择：开发服务器可运行明确标注的演示流程；正式 live 模式拒绝伪装成已接通。
- 依据：原题要求核心结论来自真实字段且缺失不得静默正常化。
- 影响：演示卡片中的数值和引用仅用于验证交互与计算；不代表 A 股事实或 AI 结论。

## 2026-10-18｜按扶摇官方契约实现首个服务端数据适配器

- 问题：原题要求真实行情，扶摇官方文档可访问，但本机没有已配置的 API Key。
- 选择：按官方 REST 契约实现指数日线、交易日历和全市场快照读取；只在服务端发送 `X-api-key`。演示与 live 严格分开。
- 依据：指数历史 K 线支持单指数、`1d`、毫秒级日期参数；交易日历覆盖近一年；A 股行情快照支持分页。真实调用、标的权限、分页上限及展示授权仍待凭据验证。
- 影响：带有效扶摇 Key 的运行环境可查询指数历史；只对匹配最近已完成交易日的完整快照计算宽度。旧历史日期不拿最新快照填补。iFinD 尚未接入；运行时模型适配器已编写，但等待真实凭据验证。

## 2026-10-18｜模型只归纳真实证据

- 问题：如何在模型输出不可靠时保留可验证的行情事实。
- 选择：用服务端 OpenAI Chat Completions 兼容接口生成结构化归纳；摘要、观察、反证必须引用当前报告中的证据 ID；无效引用或交易指令会使 AI 报告失败，但不丢弃行情快照。
- 依据：用户要求结论可回溯，并区分模型生成解释与代码计算事实。
- 影响：模型计划与报告适配器和替身测试已完成；模型只能选择受限维度，由代码映射为固定白名单接口与参数。实际模型、供应商数据及部署环境仍待凭据验证。
