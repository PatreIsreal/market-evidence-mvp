# 实现决策

## 2026-10-18｜先建立可运行的单体工程

- 问题：如何在 24 小时内交付可部署页面与服务端主链路？
- 选择：沿用 Sites Vinext 模板，React／TypeScript 统一实现页面、接口和计算。
- 依据：项目文件夹无代码；本地模板和 Sites 托管可用。
- 影响：不引入单独 Python 服务、数据库或任务队列。

## 2026-10-18｜开发期默认使用合成演示数据

- 问题：当前没有已验证的扶摇／iFinD 接口或模型 API 凭据，能否先展示流程？
- 选择：开发服务器可运行明确标注的演示流程；正式 live 模式拒绝伪装成已接通。
- 依据：原题要求核心结论来自真实字段且缺失不得静默正常化。
- 影响：演示卡片中的数值和引用仅用于验证交互与计算；不代表 A 股事实或 AI 结论。

## 2026-10-18｜按扶摇官方契约实现首个服务端数据适配器

- 问题：原题要求真实行情，扶摇官方文档可访问，但本机没有已配置的 API Key。
- 选择：按官方 REST 契约实现指数日线、交易日历和全市场快照读取；只在服务端发送 `X-api-key`。演示与 live 严格分开。
- 依据：指数历史 K 线支持单指数、`1d`、毫秒级日期参数；交易日历覆盖近一年；A 股行情快照支持分页。真实调用、标的权限、分页上限及展示授权仍待凭据验证。
- 影响：带有效扶摇 Key 的运行环境可查询指数历史；只对匹配最近已完成交易日的完整快照计算宽度。旧历史日期不拿最新快照填补。iFinD 尚未接入；运行时模型适配器已编写，但等待真实凭据验证。

## 2026-10-18｜模型只归纳真实证据

- 问题：如何在模型输出不可靠时保留可验证的行情事实。
- 选择：用服务端 OpenAI Chat Completions 兼容接口生成结构化归纳；摘要、观察、反证必须引用当前报告中的证据 ID。完整报告无效时重试简化模型结论，再失败则生成明确标记的规则结论；无效模型内容不会进入报告，也不丢弃行情快照。
- 依据：用户要求结论可回溯，并区分模型生成解释与代码计算事实。
- 影响：模型计划与报告适配器、简化结论恢复、规则兜底及替身测试已完成；Sites v13 公开端到端已验证恢复分支。模型只能选择受限维度，由代码映射为固定白名单接口与参数。

## 2026-10-18｜区分快照就绪时间与行情归属日

- 问题：扶摇全市场快照的 `timestamp` 显示周日，但最近完成交易日是周五；把两个日期直接比较会错误地将有效的最近收盘快照标为过期。
- 选择：按扶摇文档将 `timestamp` 解释为数据就绪时间；非交易时段用交易日历确定行情归属日，并在证据里同时展示两个时点。交易日 09:15—16:00 不取最新快照，避免与前一交易日收盘日线混用；历史阶段不回填宽度。
- 依据：2026-10-18 全市场分页返回 5,580 条；18 只跨页样本的 `last_price` 均与 2026-10-16 日线收盘相同。全量快照计算出 3,301 上涨、2,127 下跌、138 平盘、14 条价格缺失。
- 影响：最新日期宽度可以通过 MVP 真实数据门槛；本次 `snapshot.timestamp` 原有日期不再被误判为交易日。样本核对与快照自身 `prev_price` 的个别差异保留在能力文档中。

## 2026-10-18｜模型报告数值必须由引用证据支持

- 问题：只验证证据编号存在，仍可能让模型引用真实编号却改写其中的数值。
- 选择：对摘要、观察和反证中的数字逐条与其引用证据的数值、时点、口径及指标名核对；仅允许原值和常见一至两位小数舍入。完整报告无法通过校验时进入简化结论恢复；仍失败则使用经核验事实生成标注清楚的规则报告。
- 依据：完成判定要求关键结论能回到原始字段；计划 C19 要求覆盖模型改写数值。
- 影响：数值越界、模型超时、坏 JSON、极端比率和零分母新增回归测试；公开端到端验证了完整报告校验失败后的简化模型恢复路径。
